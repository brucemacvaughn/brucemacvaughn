Drawer 5 · Field Guide

How skills work

A skill is a folder of know-how Claude loads only when it's needed: instructions, plus optional scripts and reference files. Here's what's inside one, where it lives, and what to do after you add it.

What's in a skill folder

youtube-notes/
├── SKILL.md          ← required: frontmatter + instructions
├── scripts/
│   └── transcript.py ← run by Claude, never loaded into context
└── reference.md      ← read only if SKILL.md points to it
SKILL.md starts with frontmatter
---
name: youtube-notes
description: Pull a YouTube transcript and turn it into notes. Use when the
  user shares a YouTube link or asks what a video says.
---

# YouTube notes
1. Run scripts/transcript.py with the video URL …

The description is the trigger. Claude reads every skill's description and loads the full skill when your request matches it. Write it the way you'd ask for the task.

Where skills live

ScopePathWho gets it
Personal~/.claude/skills/<name>/SKILL.mdYou, in every project on this computer
Project.claude/skills/<name>/SKILL.mdEveryone who works in the repo (commit it)

claude.ai accountUploaded as a .zip in claude.ai settingsclaude.ai chat, Cowork and cloud sessions. Synced down to Claude Code.

A skill in ~/.claude/skills stays on your computer, so cloud sessions don't see it. To use it everywhere, upload it to your claude.ai account. If two skills share a name, personal wins over project.

You just added a skill. Now what?

  1. Nothing to restart. Claude Code watches ~/.claude/skills and .claude/skills and picks up new, edited or deleted skills in the session you have open.
  2. Brand-new skills folder? If that folder didn't exist when the session started, run /reload-skills once.
  3. Check it's there. Run /skills. The new skill should be in the list. Press Space on a skill to switch it on or off, then Esc to save.
  4. Try it. Type / and start the skill's name, press Tab to complete it, then Enter. Or just ask for the task in plain words and let the description trigger it.
  5. Confirm it loaded. Press Ctrl+O to open the transcript and look for the skill being invoked.
  6. Installed a plugin instead? If the install summary says Run /reload-plugins to apply, run /reload-plugins. Plugin skills show up as /plugin-name:skill-name.
  7. Check the cost. /skill-doctor shows each skill's context cost and which ones you never use.

Before you install someone else's skill

  • Read the whole SKILL.md. Every line of it becomes an instruction Claude will follow.
  • Open every script. Look for network calls, file deletion, or anything that reads keys or tokens.
  • Check allowed-tools in the frontmatter. A skill that pre-approves Bash or web access deserves a closer look.
  • Prefer maintained repos: recent commits, real stars, a license, issues that get answered.
  • Pin what you install. Copy a known version instead of pulling the latest each time.

The Safety read tab in every preview asks Claude to do this pass for you. It's a second opinion, not a guarantee.
